# Scenes Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the Layout feature with Scenes: named sets of groups, each group playing its own effect on its own devices, with the engine running several effects at once.

**Architecture:** The spine gains `scene.rs` (lights, groups, scenes). `canvas-core` gains an arrangement planner that turns a group's ordered members into sample points on that group's own 320x200 canvas, and the engine renders one canvas per group and merges the results per adapter device. The daemon stores `lights.json` and `scenes.json`, migrates `layouts.json` once, and serves a whole-scene write API. The editor's first page becomes a list of groups with live LEDs. Layout code is deleted last.

**Tech Stack:** Rust (canvas-proto, canvas-core, canvas-daemon, canvas-html), axum, serde, ts-rs; Next.js static export, React, vitest, CSS modules with the tokens in `app/web/src/styles/`.

**Spec:** `docs/superpowers/specs/2026-11-12-scenes-design.md`. Read it first. This plan argues from it. Its two sibling specs (chain setup, patterns) are later releases and are out of scope here.

## Review Focus

Inputs the spec implies and that are most likely to bite. Each has a test in the task named.

1. **A device drops and returns mid-scene with a new adapter index.** Its lights stay in their groups and light again. (Task 5, `reconnect_keeps_group_membership`)
2. **A zone's LED count changes while its light is in a group.** The plan is rebuilt; no frame of the old length is sent; no panic. (Task 4, `resize_rebuilds_plan_without_stale_frame`)
3. **A group names an effect that no longer exists** (deleted HTML file). That group is dark and flagged; every other group runs. (Task 6, `missing_effect_darkens_only_its_group`)
4. **Two editor windows write the same scene.** The second write is refused as a conflict and nothing is overwritten. (Task 6, `stale_rev_is_a_conflict`)
5. **`scenes.json` is damaged or hand-edited** (a light in two groups, an empty group, an `active` that names nothing). The daemon starts, repairs or quarantines, and the lights are on. (Task 5, `damaged_scenes_file_still_lights_everything`)

```rust
pub struct LightSamples {
    pub light: LightId, pub device_id: DeviceId,
    /// Index of this light's first LED in its device's frame (zone order, then the slice start).
    pub frame_start: u32,
    pub leds: Vec<LedSample>,
}

/// A member that names no light, or a light whose device is absent, is skipped.
pub fn build_group_plan(members: &[LightId], mode: GroupMode, lights: &[Light], devices: &[DeviceInfo]) -> GroupPlan;
/// The LED count a light has now: its slice's count clamped to the zone, or the zone's count.
pub fn light_led_count(light: &Light, devices: &[DeviceInfo]) -> u32;
```

Rules from the spec, pinned:
- Flow across: slot i spans x from `320 * (leds before i) / total` to `320 * (leds through i) / total`, full height. A member with 0 LEDs gets no slot.
- Each its own: every slot is the whole canvas (0,0,320,200).
- In a slot: Strip puts LED j of n at x = slot.x + slot.w * (j + 0.5) / n, y = slot mid-height. Ring puts LED j at angle `-90deg + 360deg * j / n` on the largest circle that fits the slot with a 4px inset, clockwise. Grid uses the zone's `ZoneKind::Matrix` map to fill the slot, gaps skipped; a Grid light on a non-matrix zone falls back to Strip. Single reads the slot's centre.
- `reversed` reverses LED order inside the light.
- Each `LedSample.bounds` is the cell around the centre, clamped to the canvas, at least 1px.

Behaviour to build:
- After `set_scene` the loop is in scene mode: each group owns a canvas, an effect, props and a plan. `set_layout` after `set_scene` switches back (kept until Task 12 so `main`'s code paths still run in tests).
- Per frame: for each group, run its effect behind `guarded_call`, sample its plan, scale by the group's brightness. Then build each device's frame by writing every light's colours at `frame_start`. LEDs nothing wrote are black. Then apply global brightness, warmth and white balance as today, and submit to the device's sink.
- A group whose effect panics is marked failed with the panic text, writes black, and is not called again until its effect is replaced. Other groups are unaffected.
- `Plays::Off` arrives as `effect: None`: the group writes black.
- Inputs (audio, screen) are read once per frame and passed to every group.
- `fade: true` blends each device's last sent frame into the new scene's frames over `SCENE_FADE_MS`. `fade: false` cuts.
- The light preview sink gets a `LightFrame` at most 15 times a second, with colours after group brightness and before the global stages.
- A device topology change (count or zone size) rebuilds every group's plan before the next frame; a frame built for the old size is dropped, as the layout path does today.
- Apply the fallback Task 1 recorded, if it recorded one.
- Render scale and sampling are fixed in scene mode: pick one of each from Task 1's numbers, name them as constants in `scene_engine.rs`, and write the reason beside the numbers in `docs/benchmark.md`.

Rules:
- Start-up applies the active scene (`fade: false`). Setting a scene applies it with `fade: true`.
- `PUT SCENE`: validate with `validate_scene`; 409 with the current scene when `expected_rev` differs; on success `rev` += 1, save, apply, answer the new scene.

- `POST SCENES` with `copy_of` copies groups with fresh group ids; without it, makes one `Everything` group holding every light, `Plays::Off`.
- `DELETE SCENE` refuses the last scene (409). Deleting the active scene makes the first remaining scene active and applies it.
- `PATCH GROUP_PROPS` and `PUT GROUP_BRIGHTNESS` call the engine's per-group setters, save, bump `rev`, and do not rebuild the group.
- `POST EFFECT_ACTIVATE` with `groups: None` sets every group of the active scene to that effect with the effect's starting values; with names, only those groups.
- Starting values are `EffectsFile.saved[effect]`. `PATCH EFFECT_DEFAULTS` writes them. A group that already plays the effect is not changed by it.
- `EFFECT_ACTIVE_PROPS` and the layout routes keep answering until Task 12, so the old page still works on this branch.
- `POST LIGHTS_FLASH` uses the identify override: the named lights' runs white, everything else black, the same watchdog. Several lights at once is new: extend the override's target to a list of runs.
- `GET PREVIEW_LIGHTS` streams `LightFrame`s as binary: per light a u16 id index, a u16 LED count, then RGB bytes; the first message is JSON mapping index to light id. Re-sent when the scene or lights change.
- `Status.active_scene` and `Status.active_effects` are filled.
