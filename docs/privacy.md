# Privacy: what leaves the PC

canvas-rgb checks GitHub (`github.com`) for updates when it starts and at most once a day while automatic checking is on. You can switch the automatic check off in Settings → Updates; "Check now" still makes a request on demand. A check can make one more GET of the feed it just read when the updater reports no manifest: the app probes that feed to tell a rate limit from being offline. That second GET can happen on the stable channel too. When you choose to install, it downloads the installer from GitHub. Setup downloads OpenRGB from `codeberg.org` while you install the app. Everything else stays on this PC: the editor and CLI talk to the local daemon on `127.0.0.1`, the daemon talks to a local OpenRGB server, and the daemon and service use a local named pipe. Clicking a link opens your browser — including the source, docs, privacy and credits links on Help & About (`iamchumby.github.io` is the docs site host) — and canvas-rgb fetches nothing else.

This is a source-level audit of the shipped product. Every claim below was checked against the file and line named in the last column. Anything not settled is listed under **UNKNOWN** instead of being guessed.

## Things that might have fetched but do not

- **HTML effects.** User effects run in a QuickJS context with no browser engine. The globals installed for a script are `window`, `document`, `console`, `Math`, `performance`, `requestAnimationFrame`, `setTimeout`, canvas helpers and the property values — there is no `fetch`, `XMLHttpRequest`, `WebSocket` or module loader. Scripts are evaluated as plain scripts, not modules with imports. Evidence: `crates/canvas-html/src/js.rs:138-164`, `crates/canvas-html/src/lib.rs:425-429`, `crates/canvas-html/Cargo.toml:13`.
- **Dependencies.** No Cargo manifest enables a telemetry, analytics or crash-reporting feature. `ureq` (CLI and tray) and `reqwest` (used only to set the updater's redirect policy) are ordinary HTTP clients aimed at the addresses above. Evidence: `crates/canvas-daemon/Cargo.toml:38`, `app/src-tauri/Cargo.toml:30,33,39` and `crates/canvas-html/Cargo.toml:12`.
- **NVML.** The service loads `nvml.dll` from System32 at run time to read GPU temperature and fan speed. It is a local driver DLL, not a network client; the daemon never loads it. Evidence: `crates/canvas-svc/src/temps.rs:22,42-47`; `docs/gpui-editor.md:46`.

## UNKNOWN

- The exact headers the updater client sends (for example its `User-Agent`) are chosen by `tauri-plugin-updater`/`reqwest`, not by this repository. Our code puts no user data in the URLs. **Settler:** capture one update check through a local proxy and read the request.
- Whether any transitive dependency or the OS resolver makes an extra DNS query on a machine that has never run canvas-rgb before. No source in this repository asks for one. **Settler:** packet capture on a clean install, with the switch in row 1 off and no click on a link.
- Whether a future installer build could add a skip for the OpenRGB download. No such option exists in the code audited here. **Settler:** a change to `installer/inno/canvas-rgb.iss` or `installer/setup.ps1`, which this audit's allow-list does not cover as a network call.

## Keeping this list true

`docs/privacy-allowlist.txt` sits beside this file. The test in `crates/canvas-client/tests/privacy_allowlist.rs` runs in CI (the `rust` job) and scans shipped source for URL hosts and connection constructors. It skips only the item carrying `#[cfg(test)]`, so production code later in the same file is still scanned. A new host or client fails the test until you:

1. add or edit the row in this file, with file:line evidence;
2. add the host, or the constructor with the repo-relative path of the file that uses it, to `docs/privacy-allowlist.txt` in the **same commit**; a constructor allowed in one file is refused in any other file;
3. run `cargo test -p canvas-client --test privacy_allowlist`.

Comments, test-only items, generated types, format-string templates and loopback/`.invalid` addresses are deliberately skipped by that scanner. It watches `http://`, `https://`, `ws://` and `wss://` URLs and these constructors: `ureq::Agent::config_builder`, `ureq::get(`, `ureq::agent(`, `reqwest::Client::builder`, `reqwest::Client::new`, `reqwest::get(`, `reqwest::blocking::Client`, `hyper::Client::`, `TcpStream::connect`, `to_socket_addrs`, `UdpSocket::bind`, `lookup_host`, `connect_async`, `new WebSocket`, `fetch(`, `XMLHttpRequest`, `sendBeacon`, `EventSource`, `Invoke-WebRequest`, `Invoke-RestMethod`, `System.Net.WebClient`, `tauri_plugin_updater` and `plugin:opener|open_url`. The test also asserts the counts rather than leaving them unchecked: it currently scans 483 source files, 4 outbound hosts and 8 connection constructors; a change to any of those numbers fails the test.
